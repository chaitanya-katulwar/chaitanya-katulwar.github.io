Overview

Prism v2 is the single Figma source of truth for every BookMyShow product surface. Previously, I created Lexicon as a component library that operated alongside an existing legacy design system. As product complexity grew across Android, iOS, and Web, I architected and now manage Prism v2 from the ground up — a complete four-layer design system that eliminates component detachment, enforces 100% token compliance, and enables automated MCP machine readability.

The system serves three engineering platforms from one master file, resolving 363 variables, 55 styles, and 295 components without a single hardcoded value.

1. Four-Layer Token Architecture

Prism enforces an unbreakable 4-layer resolution hierarchy. Primitives hold raw values with no meaning; components bind strictly to semantic tokens or composed styles, never reaching into primitives directly.

// Theme Engine

2. Semantic Color Modes

Primitives are single-mode and never flip. Theme switching in Prism is handled exclusively by the 70 Semantic Color Tokens in Layer 2, divided into two distinct functional groups:

• themes/ (54 tokens): Tokens that invert with the mode. Surface backgrounds, text ramps (text/primary flips from #1A1A1A in Light to #FFFFFF in Dark), and greys (g0 is white in Light and near-black in Dark).
• accent/ (14 tokens): Tokens that hold brand identity across themes, shifting luminescence only enough to maintain WCAG contrast.

// Machine Readability

6. File Structure Standards

Prism guidelines govern how product screens are built across the company so that designs are machine-parsable via Model Context Protocol (MCP) and ready for adaptive layouts (phones, foldables, and tablets). Below are visual blueprints from the production specification.

01 · Screen Skeleton: Mandated separation of fixed Header, Scrollable Content frame, and optional Bottom bar/sheet.
02 · Decoupled Spacing: Section Margins (pink side padding) separate from Page Spacing (green gaps) so layouts reflow cleanly.
03 · Level Naming: Strict f1/section_title and f2/carousel/ naming standards enabling automated MCP code generation.
// Geometry Standards

7. Concentric Inset Geometry

When an inner container is nested inside a rounded card, applying an identical radius creates an optical distortion where corners look pinched. Prism locks 4 concentric inset radius families (a, b, c, d) using the mathematical formula: R_inner = R_outer − Padding.

// Concentric arc curvature calculation

Pre-Solved Aspect Dimensions

• 66 Pre-solved Image Dimensions: Image aspect ratios (2:3, 3:2, 2:1, 16:9, 3:4) are solved mathematically for width tokens a through k. Designers never compute pixel heights by hand.

• Border Tokens: border/thin resolves to 0.5px on mobile/tablet and 1.0px on desktop. A raw 0.5 value in a file is an audit failure.
